# Studio Bura site

## Case study sections

Case study pages (src/pages/ProjectDetail.tsx) are moving from exported Figma images to coded sections. The risk-triage-tool page is the reference implementation. Apply these rules to every coded section.

### Structure

- Components live in `src/components/case-study/`: `SectionGrid`, `SectionLabel`, `HeroSection`, `StatementSection`, `OverviewSection`, `DotsChain`, `PersonasSection` (with `PersonaIcons`), `OutcomesSection` (with `OutcomeIcons`), `IconSquare`, `CapabilityIntro`, `DecisionNote`, `CaseImage`, `BoardBlock`, `DecisionBlock`, `ChainDiagram`, `FloorFlow` and `AiPanel` (risk triage only), plus `RichText` and `types.ts`. Build new section types there so every case study can reuse them.
- Every section sits on `SectionGrid` (`grid grid-cols-12 gap-x-5`), inside the page's existing `max-w-container mx-auto px-4 sm:px-6`. This keeps the left edge in line with the top bar and the "Back to …" link.
- Grid spans from md up: hero heading cols 1–12 (its lines break at sentences), statement cols 1–7, capability intro cols 1–6, dots cols 2–11, left blocks cols 1–3 (Overview left, Personas), right blocks cols 8–12 (`md:col-start-8 md:col-span-5`: Overview right, How might we). Left and right blocks in one section are top-aligned. Below md every block is `col-span-12`, stacked in DOM order.
- Board block (`BoardBlock`): DecisionNote cols 1–4 and the screenshot cols 6–12, top-aligned; caption 12px under the screenshot in cols 8–10; the second screenshot 20px under the caption, cols 6–12. The figure is a subgrid (`grid-cols-subgrid grid-rows-subgrid`) so its caption sits on page columns. The side annotation (text cols 3–4, leader across col 5, centred at a percentage of the screenshot's height) starts at xl; between md and xl it sits under the screenshot in cols 6–7, because the DecisionNote can grow into its spot. Give every item placed on a row an explicit start column too, or auto-placement adds columns past 12.
- Floor flow (`FloorFlow`): below xl one left-aligned column in DOM order; from xl its own 5-column grid inside the content width, `[phone 16rem] [arrow 1fr] [phone] [arrow 1fr] [phone]` (phone 1 starts on col 1, phone 3 ends on col 12). The desktop flow needs 3 × 256 + 2 × 152 (the widest arrow label plus breathing room) = 1072px of content, so xl (1280) is the first breakpoint where it fits. Captions get their own row (captioned phones are subgrids over rows 1–2), so all phones start on one line. A note that belongs to a phone sits in that phone's cell, so a taller neighbour can't push it down. The takeaway is a `<p>` in the statement style, exactly cols 1–4: its cell spans the whole flow row and holds a 12-column grid, with `pointer-events-none` on the cell and `-auto` on the text.
- AI panel (`AiPanel`): screenshot blocks stacked 16px apart (`xl:gap-y-4`) so they read as one panel, images cols 6–12, one grid row per block from xl. Each note uses the board annotation pattern: text cols 3–4 and a 1px `line` leader across col 5 to the image. A DecisionNote spans cols 1–4 (it needs its label column), with its right edge and leader in the same place. The note's cell stretches over the row, and the note is centred on `noteAt` of the block's height (default 50%; the page passes it next to the image, e.g. 25% where the leader points at the chain timeline). Below xl: images full width, each note 12px under its image without a leader, 32px from a note to the next image.
- The DOM follows the stacked (mobile) order at every width; wider layouts place items with explicit grid positions. Screen readers then get one sequence at every width.
- Decision block (`DecisionBlock`): a DecisionNote beside captioned screenshots of the outcomes it leads to. From xl: DecisionNote cols 1–4 and the screenshots cols 6–12, stacked, top-aligned (the note's first line and the first caption share a line). Each caption sits 16px above its screenshot (`captionPosition="top"`, `captionClassName="mb-4"`, ink-muted as in Figma), and a screenshot to the next caption is 16px. Below xl: note, 32px, then captions and screenshots full width.
- Outcomes (`OutcomesSection`), the closing section, the same pattern as Personas / How might we: from xl, the label (the section's h2) and three outcomes in cols 1–5 (label to first item 12px, items 64px apart); each outcome is an `IconSquare`, an h3 in `heading-3` and `body` text, 12px apart. The closing statement is a `<p>` in the statement style with `text-pretty`, cols 8–12, top-aligned with the label. The disclaimer (`annotation`, `ink-muted`) sits 64px under the last item, cols 1–5. Below xl: label, outcomes, statement, disclaimer, full width, 64px apart.
- Icon squares (`IconSquare`): 56px (`size-14`), `rounded`, `bg-project-accent`, `text-surface`; shared by personas and outcomes. Figma draws them at 56.67 and 52; both are 56 in code.
- Where a coded stack sits between existing images or animations, give it the section gap above and between its sections, and leave out padding that would double an image's own built-in blank space. A block between two coded stacks (the risk page's screen recording) has no margin of its own: the stack above sets the gap with its bottom padding, the one below with its top padding. The last coded section has no bottom padding; the page's shared blank space before the footer sets that gap.
- All copy lives in the project's `caseStudy` entry in `src/data/projects.ts`, typed by `CaseStudyContent`. JSX only renders it.
- Project accent colours are HSL channels in `caseStudy.accent` / `accentStrong`, set as `--project-accent` / `--project-accent-strong` on the case study's page wrapper.
- The project header (title, Project, Type) is shared by all projects; leave it as it is.

### Values

- Figma CSS is reference only. Translate typography, colour, spacing, gap, padding and radius into Tailwind. Layout comes from the grid spans; position, left/top, fixed width/height, opacity and vector layers are left out.
- Colours: only the tokens `ink`, `ink-muted`, `surface`, `surface-muted`, `project-accent`, `project-accent-strong`, `line` (tailwind.config.ts; Figma variables ink, muted, surface, surface-muted, accent, accent-strong, line). Text is `text-ink` or `text-ink-muted` on light backgrounds, `text-surface` or `text-surface-muted` on `project-accent`, always at full opacity.
- `surface-muted` (#E2E3E7) is light text and borders on `project-accent`, and the grey background behind `ink-muted` text (ghost slots, the UNPLACED box). It's set so both reach 4.5:1; keep it there if it changes. `line` (#A7A7A7) is only for decorative 1px leader lines, which are `aria-hidden`. Diagram connectors are `ink-muted`.
- Text styles: only the fontSize tokens `hero`, `statement`, `heading-3`, `body`, `body-sm`, `label`, `annotation` (14/20), `diagram` (12/16, diagram card text) and `diagram-mono` (10/12, with `font-mono`, the system monospace stack; no web mono font). `hero`, `statement` and `body` switch size at md through CSS variables in src/index.css, so one class covers both sizes. `heading-3` is 24/32 at every width. The Overview's h3 (“The plan was never the problem.”) uses `statement`, so it keeps the 24/32 → 32/48 switch. Weight is a separate class (`font-bold`); "Body small bold" is `text-body-sm font-bold`. Load any new Poppins weight in the Google Fonts link in index.html (it loads 300–700); never rely on faux bold.
- A new fontSize token must also go in the `font-size` list in src/lib/utils.ts. Otherwise `cn()` (tailwind-merge) reads it as a colour and drops it when a colour class like `text-ink` sits next to it.
- Spacing uses the default Tailwind scale (Figma spacing is rounded to it). An arbitrary value is a last resort: add a comment saying why, and report it.
- Vertical rhythm: one section gap, 128px from md and 64px below (`gap-16 md:gap-32` on the stack of coded sections, the same as padding below the last). Apply it on the stack, not per element.
- Header to hero: from md, `pt-32` on the stack. Below md, the visible gap (header's last text line to hero text) is 64px: the header ends in 48px of padding, so the stack gets `pt-1.5`.
- An animation with built-in empty space gets a negative margin that removes that space, so the visible gap is still the section gap. For RiskHeroAnimation that is `-my-[6%]` (120 of 2000 viewBox units; percent margins follow the width).
- Dots (`DotsChain`): one rule at every width, dot size = gap = row width / (2 × count − 1), so the row always fits on one line. The raised dot sits `--dot-raise` diameters above its empty slot (1 at rest), ready to animate. The row is `aria-hidden` with an `sr-only` sentence from the copy data.
- Annotations: `annotation` style in `ink-muted`. On desktop they hang off the element they describe with a 1px `line` leader; below md (and wherever a layout stacks) they go under the element, without a leader.
- Decisions (`DecisionNote`): a `<dl>` of rows, label (DROPPED / CHOSE / EDGE, label style, `ink-muted`) in a 64px column (EDGE too, though Figma's is 36), an `aria-hidden` dash in a 28px column, so the text starts 92px in. The text is `annotation` style: DROPPED is `ink-muted` and struck through; CHOSE and EDGE are `ink`. Rows are 8px apart.
- Screenshots (`CaseImage`): a `<figure>` with alt text from the copy data, `width`/`height` from the file, lazy loading, and an optional figcaption (annotation style, 12px below, or 12px above with `captionPosition="top"`; captions are `ink-muted` unless the section says otherwise: the floor flow's captions are `ink`). `imgClassName` styles the image itself.
- Phone screenshots: 256px wide (`w-64`, or the content width if narrower), `rounded-3xl` with the `shadow-phone` token (tailwind.config.ts, Figma's phone shadow). The files are cropped to the phone with transparent corners and no baked-in shadow or margin, 512px wide WebP.
- Flow arrows: the label (the tap that leads on, annotation style, `ink-muted`) is a real `<p>`; the 1px `line` and its 6px filled head are `aria-hidden`. 96px long on desktop, 48px pointing down when stacked. Files are WebP in `src/assets/projects/`, about 2x the widest display width (1600px for cols 6–12).
- Wide diagrams (`ChainDiagram`): fixed card sizes from Figma rounded to the scale, left-aligned, fitting at 1280 (the risk chain row is 1072px with 160px cards, so it fits from a 1120px viewport up). Card text wraps inside the card and must fit the card's height; it never overflows or runs into the padding. Where they don't fit, the diagram scrolls sideways in its own container (`overflow-x-auto`, `snap-x snap-mandatory`, `snap-start` on the cards, `role="region"` with an `aria-label` and `tabIndex={0}`), bleeding into the page gutters (`-mx-4 px-4 sm:-mx-6 sm:px-6`) so the next card shows partly at the screen edge. Text never shrinks. Parts meant to animate later take CSS variables (the lifted card: `--lift-x`, `--lift-y`, `--tilt`).
- Icons are inline SVG with `stroke="currentColor"`, coloured with a token class (`text-surface`), stroke 1.5 with `vector-effect: non-scaling-stroke`. Exception: illustrative icons that fill their square (the outcome icons) use 1px non-scaling strokes and the full Figma frame as viewBox; small UI icons keep 1.5. Draw coloured backgrounds as divs with tokens, not inside the SVG. Icon colours are tokens too: white → `currentColor` (surface), dark dots → `project-accent-strong`, ghost outlines → `surface-muted`.
- Inside a block: label, h3 and text are 12px apart (`gap-3`). Blocks in a column are 64px apart (`gap-16`). Paragraph gap = one line of that paragraph's style (`body` gap-7, `body-sm` gap-6).

### Text

- Copy uses curly quotes and apostrophes (“ ” ’), never straight ones.
- Each paragraph is its own `<p>`. An intentional line break is a new line in the copy data, rendered as `<span class="block">`; markup has no `<br>`. Where a break only suits the wide layout, pass `breakFrom="xl"` to `RichLines`: the lines are `xl:block` spans joined by a space, and below xl the text wraps naturally (the outcomes headings and closing statement).
- Headings use `text-balance`. To keep a phrase together (e.g. “the floor”), put a non-breaking space in the copy data (`\u00A0`), never a manual break. A hyphenated word that must not split (“at‑risk”) takes a non-breaking hyphen (`\u2011`); Poppins has the glyph.
- Statement-style paragraphs that aren't headings (takeaways) use `text-pretty`, so the last line is never one short word.
- Hierarchy: the page's only h1 is the project title in the header. Hero heading, statement and capability intro headings are h2; headings inside blocks are h3. Labels (ROLE, THE PROBLEM, …) are `SectionLabel`, a `<p>`. Where a label is the section's only heading (WHAT IT’S DESIGNED TO CHANGE), it's `SectionLabel as="h2"`: label style, h2 semantics.

### Don't touch

- Only change the page you're working on. The top bar, RiskHeroAnimation and the other animation components, other projects, and ProjectDetail.tsx's shared layout stay as they are beyond what the page needs.
- When a coded section replaces an image, remove the image from the page but keep the file in the repo until the user says to delete it.

### Checking against Figma

- With the dev server running, `?overlay=1` draws the Figma exports over their sections at 50% (pass `overlay` to the section component). When an export starts above or below the section's top edge, pass `overlayOffset` (e.g. `"-56px"` for dash4b) to line it up. Exports live in `design-ref/` (gitignored), are served by the dev server by path and are never imported, so production builds don't include them. Keep it that way: a string path behind `import.meta.env.DEV`, never an `import`.
- Check at 1440 (the Figma width: 1352px content), 1280, 390 and 320, then run `npm run build`. For a section with its own breakpoint, also check both sides of it (FloorFlow: 1280 and 1024). For a section that scrolls sideways, confirm it fits at 1280 and that at 390 and 320 only its container scrolls, not the page.
